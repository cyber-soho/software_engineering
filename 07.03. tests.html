Topic 3 — Software Coding & Software Testing · flash-cards and formative self-test · Cyber.SoHo Educational Hub

Write code that other people can read, then prove with tests that it does what the requirements say.

This Study Hub holds the terms and the reasoning of Class 7 — readable code (names, comments, docstrings, small functions, code review and commit hygiene); the five types of testing — unit, integration, system, user acceptance and performance — with verification, validation, the V-model and a test plan with exit criteria; black-box test design (equivalence partitioning, boundary value analysis, decision tables, error guessing); white-box test design (statement and branch coverage, the flow graph, V(G) (cyclomatic complexity) and basis paths); and TDD (Test-Driven Development), test doubles, debugging and defect reports. Use the tabs above to switch between memorising the terms and testing yourself on the reasoning.

How to use it

  • ✅Flip the flash-cards until every front side brings back the back side from memory — the “what”.
  • ✅Take the quiz to practise the reasoning — the “why”. An MCQ (Multiple-Choice Question) has one right answer among four options; an MSQ (Multiple-Select Question) has six options and shows, in round brackets next to the question, how many right answers are expected. A multiple-select question earns its point only when you find all the right answers and nothing else.
  • ✅Every question has a hint, an immediate answer, a button that reveals the answer, and a note under every option saying why it is right or wrong. Finish the quiz to see your breakdown by lesson and the questions to work on; then repeat it with “Shuffle: on”.
  • ✅Everything here comes from the Class 7 module and its lecture: re-read the lesson whenever a note surprises you, and run the five demo programs step by step to see the ideas move.
